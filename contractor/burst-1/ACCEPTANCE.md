# Приёмка рывка 1

Сдача — файл `deliverables/character_v<NN>.blend` (текстуры упакованы: File → External Data →
Pack Resources; размер до 90 МБ, иначе напиши в `QUESTIONS.md` — включим LFS), скрипт сборки
`deliverables/scripts/build_character.py` с тем, что он импортирует (пункт 5; сторонние
`.blend`-заготовки скрипт открывать не может — геометрию, которую ты делал руками, клади
рядом как `.obj` и читай её из скрипта), плюс заполненные `REPORT.md` и `LICENSES.md`. Каждая версия — новый номер, старые не удаляются.

## Проверки, которые ты запускаешь сам перед сдачей

Один раз: Blender 5.2.1 LTS и OpenImageIO по `benchmarks/bakeoff/01J7B000000000000000BAKEXP/slice/REBUILD.md`
(шаги 1–2) и Python-зависимости проверок: `python3 -m pip install -r requirements-dev.txt`
(или venv в `.venv/` — скрипт найдёт его сам). Затем из корня репозитория, с Blender в PATH:

    slice/check_asset.sh deliverables/character_v01.blend /tmp/asset_check

Скрипт прогоняет ровно ту цепочку, которую проходит манекен: проверка структуры сцены →
проверка силуэта на сквозные дыры (шаг 1b, секунды) → экспорт шота → проверка экспорта → проверка Alembic → пробный рендер трёх видеокадров (первый,
самый быстрый поворот головы, самый открытый рот — `slice/pick_frames.py`) и стилла
(64 сэмпла, 25 % — порядка десяти-пятнадцати минут на Apple M4; меньше сэмплов нельзя, гейт компоновки на них не сходится) → сборка бандлов → компоновка → тест обратной проекции (голова,
собранная только из экспортированных данных, ложится на рендер). Последняя строка должна быть
`ASSET_CHECK_OK`. При ошибке скрипт останавливается на шаге и пишет, что не так; полный лог
— `/tmp/asset_check/last_step.log`. Хвост лога вставь в `REPORT.md`. Между сдачами можно
гонять быстрый вариант — `CHECK_ASSET_QUICK=1 slice/check_asset.sh …`: только первый видеокадр,
без стилла, итог `ASSET_CHECK_QUICK_OK`; для сдачи он не считается (Q22).

Что означают типичные ошибки:

| Сообщение | Причина |
|---|---|
| `collection C_… missing`, `bone … missing`, `material … missing` | имена не по контракту |
| `ray visibility is not shadow-caster-only` | у объекта головы/волос не выставлены флаги из TASK §6 |
| `SOCKET_HEAD not bone-parented to the head bone` | сокет не привязан к кости `head` |
| `C_HEAD: exactly one render-visible mesh must carry SOCKET_BOUNDARY` | кольцо не на одном меше-оболочке (нет или несколько) |
| `rest gap … ≥ 0.005` | кольца головы и тела не совпадают в покое |
| `SOCKET_BOUNDARY count mismatch` / `weights are not distinct` | кольца разного размера или веса не заданы порядком |
| `hair Curves with points cannot be re-projected` | волосы не мешем |
| `C_HAIR must hang rigidly on SOCKET_HEAD` | меш волос деформируется (шейпкей, драйвер, скиннинг) — с v02 экспорт это проверяет |
| `SILHOUETTE_ERROR … see-through hole at the head↔body seam` | сквозная щель у шва: чаще всего горловина одежды не смыкается на шее — смотри картинки в `<выход>/silhouette/views/` |
| `round-trip FAIL` | голова не садится обратно по экспорту — чаще всего голова не следует за сокетом или лежит внутри тела |

## Что мы проверяем при приёмке

1. `check_asset.sh` проходит у нас на 25 % и на 100 % (пороги пока предварительные; если
   на 100 % что-то падает по порогу, а не по структуре, это наша калибровка, не твоя ошибка —
   мы скажем).
2. Визуально: голова — настоящая голова, шов на шее чистый, кожа открыта на голове, шее,
   кистях; волосы отдельным ассетом; никаких головных уборов и очков.
   **Добавки для v02 (2026-09-17, Q17, Q19, Q20)** — превью в `deliverables/previews/`, их смотрит
   владелец: брови, волосы и одежда больше не выглядят заглушками (Q20; превью front /
   three_quarter / side / head); (а) рендер или плейбласт шеи в том максимальном повороте головы относительно
   груди, который будет в `SHOT_002`, и в нейтрали рядом — шея не защипнута и не смята, шов не
   разошёлся; (б) глаза при `lid_aperture` = −1, −0,5, 0, +1 и при −1 вместе с `blink` = 1 —
   на −1 веко сомкнуто полностью, в сочетании не проходит сквозь глаз, на −0,5 не режет
   глазное яблоко; (в) тело под одеждой удалено — на превью поворота нет дыр у воротника,
   рукавов и подола (Q21). **С 2026-09-17 пункт (в) у шва голова↔тело меряется, а не смотрится
   глазами:** `slice/check_silhouette.py` — шаг 1b внутри `check_asset.sh`, отдельно запускать
   не нужно. Он ставит риг в нейтраль и в максимальный поворот головы, рендерит объявленные
   ракурсы на прозрачном фоне и ищет замкнутые области фона внутри силуэта — каждая такая
   область это луч, который вошёл в силуэт и вышел наружу. Падает, если луч проходит ближе
   0,12 м от `SOCKET_HEAD` и область больше 50 пикселей; щель между опущенной рукой и корпусом
   дальше и в вердикт не идёт. В сообщении названы объекты, между которыми дыра, картинки —
   в `<выход>/silhouette/views/`.
   **Обновлено 2026-09-19 (сделай `git pull`):** (1) поза — поворот вокруг оси кости Y, а не Z,
   и инструмент сам меряет поворот сокета после позирования и падает, если он не тот (в первой
   версии по Z выходил наклон вбок на 60° при 7° поворота); (2) `C_HAIR` в проверку больше не
   входит — у волос свободные края, они и выдумывают щели, и прячут настоящие; (3) шов
   обходится 36 ракурсами (12 азимутов × 3 наклона), потому что щель v02 видна лишь из одного
   30-градусного сектора. Итого 80 рендеров, около 20 секунд.
3. `LICENSES.md` заполнен для каждого стороннего элемента.
4. В файле нет ничего из §7 задания.
5. Сдача пересобирается (Q11). Шаг 0: установка MPFB2 версии и, если есть, коммита из
   `LICENSES.md`, источник установки записан; шаблон из `slice/scene_template.py` на
   указанном в `REPORT.md` коммите публичной копии; затем
   `blender -b template.blend --python-exit-code 2 -P deliverables/scripts/build_character.py -- --out deliverables/character_vNN.blend`.
   Пересобранный файл: (а) даёт `BUILD_OK` и `check_scene.py` без ошибок; (б) проходит
   `check_asset.sh`; (в) его `exports/` совпадает с экспортом присланного файла по правилу
   `rebuild_shot.py` — все файлы побайтно, `proxies.abc` по хэшу геометрии из meta-файла,
   `export_manifest.json` по полям без хэша abc; (г) хэш содержимого сцены
   (`blender -b <file> --python-exit-code 2 -P slice/blend_content_hash.py -- --json <out>`)
   равен хэшу присланного файла. Байты `.blend` не сравниваются. Сборка без случайности; если
   seed нужен — он фиксирован и записан в отчёт. **Допуск другой машины (2026-09-16, по v01):**
   твоя сборка на Linux CPU и наша на macOS Metal расходятся на ≤ 1,3e-7 м во всех числах
   (порядок операций float32) — это не расхождение. В `slice/conventions.json` → `rebuild`
   объявлен допуск **1e-5** на каждое число: файл экспорта, который не совпал побайтно,
   сравнивается численно; `proxies.abc` — численно через `slice/compare_alembic.py`; при разных
   хэшах содержимого сравниваются дампы канонического содержимого (`blend_content_hash.py
   --dump`) тем же допуском. Всё, что за допуском, и любое нечисловое отличие — отказ.
   Пункты 5 и 1 (на 25 %) мы выполняем одной командой — `slice/accept_delivery.py` (лежит и в
   публичной копии, читай её docstring): MPFB2 ставится в изолированный профиль Blender внутри
   каталога прогона, шаблон собирается на коммите из `REPORT.md`, дальше твой
   `build_character.py` (папка `deliverables/scripts/` копируется в каталог прогона и
   запускается оттуда; скрипт не должен открывать другие `.blend`, запускать процессы,
   копировать файлы или ходить в сеть — такое останавливает приёмку до запуска) →
   `check_scene.py` на обоих файлах → `check_asset.sh` на пересобранном и на присланном
   файле → сравнение экспортов → сравнение хэшей содержимого. Итог `ACCEPTANCE_REBUILD_OK`
   и `acceptance_report.json` с кодом выхода и логом каждого шага; отчёт прикладываем к
   вердикту в `QUESTIONS.md`. Поэтому в `REPORT.md` / `LICENSES.md` должны быть: коммит
   публичной копии, из которого собран шаблон; источник MPFB2 (ссылка на git и тег или коммит,
   либо zip) и версия его манифеста. Прогон на 100 % (пункт 1) — отдельно, той же командой с
   `--asset-check <сэмплы> 100`.

Критерий «сделано»: пункты 1–5 выполнены на одной и той же версии файла.
